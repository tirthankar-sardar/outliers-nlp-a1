# Sparse Information Retrieval System

## Overview

This project implements a **sparse, word-based information retrieval
system** on the **Cranfield collection** using **PyTerrier and Apache
Terrier**.

The current executable pipeline is:

``` text
User Query
    ↓
Preprocessing
    ↓
TF-IDF Retrieval
    ↓
RM3 Pseudo-Relevance Feedback
    ↓
Expanded Query
    ↓
TF-IDF Retrieval
    ↓
Ranked Documents
```

The project also contains/report references several retrieval
configurations that were investigated during the study, including TF,
TF-IDF, Lemur TF-IDF, Weighted TF-IDF, title boosting, and Rocchio-style
feedback. However, the **currently runnable implementation in
`outliers_run_experiment.py` and `outliers_search_engine.py` is TF-IDF +
RM3**.

The qrels are used for **evaluation only**. They are not used to select
documents or expand an individual query during retrieval.

# 8. Preprocessing

Before indexing, the documents are preprocessed.

The preprocessing stage includes the project's configured text
normalization, stopword handling, and stemming using a Porter stemmer.

The processed documents are converted into records containing:

``` text
docno
text
```

These records are passed to PyTerrier for indexing.

Queries are processed using the same preprocessing procedure before
retrieval.

------------------------------------------------------------------------

# 9. Query ID Handling

An important implementation detail is the handling of query IDs.

The queries are parsed from the `.W` sections of `cran.qry`. During
processing, the implementation assigns sequential query IDs:

``` text
1, 2, 3, ..., 225
```

This is intentional so that the processed query IDs align correctly with
the qrels used for evaluation.

This should **not** be changed casually because changing the query-ID
handling can produce incorrect evaluation results even when the
retrieval model itself is working correctly.

------------------------------------------------------------------------

# 10. How the Index Is Built

The index is built using **PyTerrier's `IterDictIndexer`**.

Conceptually:

``` text
Preprocessed documents
        ↓
PyTerrier IterDictIndexer
        ↓
Apache Terrier
        ↓
Inverted Index
        ↓
outliers_index/
```

The indexer is configured with document metadata and text:

``` python
pt.index.IterDictIndexer(
    INDEX_PATH,
    meta=["docno"],
    text_attrs=["text"],
    overwrite=True
)
```

Therefore, the directory:

``` text
outliers_index/
```

is a **Terrier inverted index created through PyTerrier**.

PyTerrier provides the Python interface, while Apache Terrier performs
the underlying indexing and retrieval operations.

# 11. Run the Experiment From Scratch

This is the recommended procedure when you want to rebuild everything.

Make sure the environment is activated:

``` bash
source ir_env/bin/activate
```

Go to the project directory:

``` bash
cd "/path/to/Outliers_VSM_Ranked_Retrieval"
```

If you are already inside the project directory, no `cd` command is

## Step 1 --- Remove the existing index

``` bash

```

This forces the program to build a new index.

## Step 2 --- Remove old experiment outputs

``` bash
rm -f index_time.txt results.txt
```

This ensures that the output files correspond to the new run.

## Step 3 --- Run the experiment

``` bash
python outliers_run_experiment.py
```

The program will:

1.  Initialize PyTerrier and Java.
2.  Load the Cranfield documents.
3.  Preprocess the documents.
4.  Parse and preprocess the queries.
5.  Load the qrels.
6.  Build the PyTerrier/Terrier index if it does not already exist.
7.  Measure indexing time.
8.  Create the TF-IDF retrieval pipeline.
9.  Apply RM3 pseudo-relevance feedback.
10. Retrieve documents again using the expanded query.
11. Evaluate the results.
12. Save the retrieval results to `results.txt`.

# 13. TF-IDF + RM3 Retrieval

The current executable uses the following retrieval model:

``` text
TF-IDF + RM3
```

The TF-IDF retriever is created using Terrier:

``` python
pt.terrier.Retriever(index, wmodel="TF_IDF")
```

RM3 is then applied:

``` python
pt.rewrite.RM3(
    index,
    fb_docs=30,
    fb_terms=15
)
```

The pipeline is:

``` text
TF-IDF
   ↓
RM3
   ↓
TF-IDF
```

In PyTerrier pipeline notation:

``` python
tfidf >> rm3 >> tfidf
```

### RM3 parameters used by the current code

``` text
fb_docs  = 30
fb_terms = 15
```

This means that RM3 uses feedback from the top 30 initially retrieved
documents and selects 15 feedback terms for query expansion.

> **Important:** The current executable uses `fb_terms=15`. Any older
> documentation stating `fb_terms=20` is outdated for the current code.

# 14. Run the Search Engine

After the index has been created, run:

``` bash
python outliers_search_engine.py -q "aircraft wing design"
```

The long form is:


3.  Loads the existing Terrier index.

6.  Displays document IDs, scores, and snippets.

# 17. Evaluation Metrics

The experiment evaluates retrieval effectiveness using:

-   **MAP** --- Mean Average Precision
-   **MRR** --- Mean Reciprocal Rank
-   **P@5** --- Precision at 5
-   **P@10** --- Precision at 10
-   **nDCG@10** --- Normalized Discounted Cumulative Gain at 10

The qrels are used to calculate these metrics.

They are **not used during query retrieval or query expansion**.

# 24. Notes About Empty Documents

During indexing, Terrier may display warnings such as:

``` text
Adding an empty document to the index
```

or:

``` text
Indexed 2 empty documents
```

A small number of empty documents does not necessarily mean that
indexing failed.

In the tested run, the index was successfully created and retrieval
completed normally despite the warning.

The preprocessing pipeline should not be changed solely to remove this
warning unless the assignment/report specifically requires those
documents to be handled differently.
